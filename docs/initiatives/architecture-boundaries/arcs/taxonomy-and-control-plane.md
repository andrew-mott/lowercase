## Change C1 - Package-tier taxonomy + control-plane research - merged (PR #341)

Settled the full package-tier taxonomy and opened the control-plane question, both grounded in real code rather than pure discussion. Genuinely iterative, not a clean discuss-then-build pass — the summary below distills the settled decisions and rejected alternatives; the research docs carry the full evidence trail.

### Discussion

- **The pure-logic tier's name went through real rejects before landing**: `use-cases`/`workflows`/`domains` (never sat right, superseded), bare `core` (too generic, risked becoming a catch-all `types` deliberately isn't). Settled on `functional core`, borrowed specifically from Bernhardt's "functional core, imperative shell" pattern — not adopting DDD wholesale, just the one term that precisely named the relationship to `services`/Operations.
- **`packages/ports`'s definition was deliberately broadened past strict hexagonal swappability.** Build-graph decoupling and test seams alone justify a port even with exactly one implementation — the defining property is "a consumer depends only on the interface," not "this will someday be swapped."
- **`packages/specs` splitting types from schema (mirroring `packages/events`) was seriously considered and rejected for now** — checked empirically rather than assumed: only 1 of 10 cross-package consumers needed just the type, the rest needed real runtime schema/parse behavior. Revisit once `json-schema-migration` actually changes the types/schema relationship underneath it.
- **The biggest naming fork: renaming `components` to "services" (real SOA/microservices vocabulary) paired with "application services," vs. keeping `components` and renaming only `packages/services`.** Rejected the former — `components` is deliberately deployment-agnostic (composability is a consequence of the event-driven property, not a commitment to any topology), and "services"/"distributed services" would claim something not earned yet. A same-axis pairing ("reactive services" vs. "application services") was floated as an alternative if renaming both was ever wanted, but wasn't needed once keeping `components` as-is resolved the friction directly. Landed: `components` unchanged, `packages/services` → `packages/app-services`.
- **The services-vs-Operations "who's the caller" test was corrected mid-discussion**, not just applied — "lives under `apps/`" turned out to be a proxy that only worked because every existing app happens to be request/response shaped. Corrected to the real test: does it orchestrate one bounded, external, request/response interaction. Surfaced by asking whether a hypothetical `apps/engine` (an extracted component with its own minimal HTTP wrapper) would need `application services` — it wouldn't, because its internal shape stays `components`-shaped regardless of which folder it's in.
- **ADR sequencing itself was a real pivot, not the original plan.** This initiative's summary originally said the output was ADRs with no execution pass. Once the taxonomy was actually settled, writing ADRs straight off discussion started to feel premature — `ui-workspace`'s own `research/state-management.md` already proved discussion alone repeatedly misses things only real code surfaces. Pivoted to proving the shape with a light organizational pass first (see `INITIATIVE.md`'s `Evolution`).
- **Control plane**: shutdown-vs-quiescing was a real, load-bearing distinction to draw (only quiescing needs to be the event-driven default; shutdown's terminality is a property of the action, not a reason to avoid events entirely) — see `research/control-plane.md` for the full reasoning, deliberately left as a fragment rather than a complete design.

Full evidence, every empirical check, and all eight tiers' complete reasoning: [`research/package-tier-taxonomy.md`](../research/package-tier-taxonomy.md) and [`research/control-plane.md`](../research/control-plane.md).

### What actually landed

- **[`research/package-tier-taxonomy.md`](../research/package-tier-taxonomy.md)** — all eight tiers given a real membership test and evidence: `types` (the four-test placement rule), `ports` (DIP broadened past strict hexagonal, the live-vs-dead litmus test), `specs` (empirically checked whether to split from `events`' precedent — decided not to, dead files found and confirmed), `functional core` (name, membership test, naming/grouping conventions, the `packages/functional-core/*` subfolder decision), `Operations` (the "exactly one port" rule justified from first principles, the wiring model confirmed via two independent code examples), `application services` (renamed from `services`, small confirmed footprint), `components` (name kept deliberately, three-property test, the critical-path/tap sub-distinction, the data-plane/control-plane split), `adapters` (origin, membership test, what they may/may not import, why they stay one package unlike the other two subfoldered tiers). Full sweep of every remaining unclassified package (`db-prisma`, `events`, `replay`, `scheduler`, `ui`).
- **[`research/control-plane.md`](../research/control-plane.md)** — new file, deliberately scoped as a fragment (control plane only, not the full event-driven-architecture question). Grounded in the actual `WorkflowRuntime`/`ObservabilityTap`/SSE-route code, not assumption. Landed the shutdown-vs-quiescing distinction, the HTTP-emits-the-same-event resolution, and the explicit scope decision (event-driven now, in-process; out-of-process extraction stays deferred).
- **`INITIATIVE.md`** — rewritten from a one-paragraph placeholder into a real Summary/Evolution/Change index/Next up/Not yet scoped doc, including the deliberate pivot away from "ADRs straight off discussion" toward proving the shape with a light reorg pass first.

**Real corrections found along the way, not just documentation of a plan that held**: `run-flow`'s `runFlow()` and `run-history`'s live exports were originally guessed as both folding into `services` — checked directly, `run-flow` is Operation-shaped, `run-history` is actually `functional-core`-shaped (zero ports), the guess was only half right. `packages/replay` was assumed barely-used going in — checked directly, it's genuinely wired into a live HTTP route (`GET .../events` → `getAllEvents`). The `types` tier's original "776 import sites, no violations" claim had an unflagged stale-`dist/` caveat, found and fixed.
